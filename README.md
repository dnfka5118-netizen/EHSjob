# EHS팀 업무관리 대시보드 - 사내 공용 서버 설치 안내

`team_calendar_dashboard.html` 하나만 각자 컴퓨터에서 열면 데이터가 공유되지 않습니다.
이 폴더의 서버를 사내 PC(또는 서버) 한 대에서 실행해두면, 같은 사내망에 있는 팀원들이
브라우저로 그 컴퓨터에 접속해서 **같은 데이터**를 함께 보고 수정할 수 있습니다.

데이터는 외부 클라우드로 나가지 않고 이 서버를 실행하는 컴퓨터 안(`server/data/state.json`)에만 저장됩니다.

## 1. 준비물

- 상시 켜둘 수 있는 사내 PC 또는 서버 1대 (Windows / macOS / Linux 모두 가능)
- Node.js 18 이상 설치: https://nodejs.org (LTS 버전 다운로드해서 설치)
- 팀원들이 접속할 사내망(같은 회사 네트워크)

## 2. 설치

1. 이 대시보드 폴더 전체(`team_calendar_dashboard.html` + `server` 폴더)를 서버로 쓸 PC에 복사합니다.
2. 명령 프롬프트(또는 터미널)를 열고 `server` 폴더로 이동합니다.

   ```
   cd server
   npm install
   ```

   (인터넷이 처음 한 번 필요합니다. 이후 실행에는 인터넷이 필요 없습니다.)

## 3. 실행

```
npm start
```

정상적으로 실행되면 아래와 같은 메시지가 보입니다.

```
EHS 팀 업무관리 대시보드 서버가 실행 중입니다.
같은 네트워크의 팀원들은 브라우저에서 http://<이 PC의 내부IP>:4000 로 접속하면 됩니다.
```

- 이 PC의 내부 IP는 Windows에서 `ipconfig`, macOS/Linux에서 `ifconfig`(또는 `ip a`)로 확인할 수 있습니다. (예: 192.168.0.15)
- 포트를 바꾸고 싶으면 `PORT=5000 npm start` 처럼 실행하세요. (기본값 4000)
- 사내 방화벽이 있다면 이 포트(기본 4000)를 내부망에서 허용해줘야 합니다.

## 4. 로그인 계정 (아이디/비밀번호)

서버를 처음 실행하면 콘솔에 아래와 같은 초기 로그인 계정 정보가 한 번 출력됩니다.

```
초기 로그인 계정이 생성되었습니다. (server/data/auth.json)
아이디: ehsteam
비밀번호: changeme123
```

이 아이디/비밀번호는 팀 전체가 함께 쓰는 공용 계정입니다(팀원별 개별 계정이 아닙니다).
**보안을 위해 처음 실행한 뒤 바로 비밀번호를 바꿔주세요.** `server` 폴더에서:

```
node set-password.js <새 아이디> <새 비밀번호>
```

를 실행하면 즉시 반영됩니다(서버를 껐다 켤 필요 없음). 예:

```
node set-password.js ehsteam SypChem!2026
```

처음 서버를 실행할 때부터 원하는 계정으로 바로 만들고 싶다면, 아래처럼 환경변수로 지정해서 실행하세요.

```
TEAM_USERNAME=ehsteam TEAM_PASSWORD=원하는비밀번호 npm start
```

(단, `server/data/auth.json` 파일이 이미 만들어진 뒤에는 이 환경변수가 무시되고 파일의 값이 우선합니다.
계정을 다시 바꾸고 싶으면 항상 `node set-password.js`를 사용하세요.)

## 5. 팀원 접속 방법

팀원들은 각자 컴퓨터 브라우저에서 다음 주소로 접속하면 됩니다. (파일을 따로 나눠줄 필요가 없습니다.)

```
http://<서버 PC 내부IP>:4000
```

접속하면 로그인 화면이 먼저 나오고, 위에서 설정한 아이디/비밀번호를 입력하면 대시보드로 들어갑니다.
로그인 상태는 브라우저에 7일간 유지되며(브라우저를 껐다 켜도 다시 로그인할 필요 없음), 서버를
재시작하면 모든 팀원이 다시 로그인해야 합니다. 화면 오른쪽 위 "로그아웃" 버튼으로 언제든 로그아웃할 수 있습니다.

로그인 후에는 자동으로 서버와 동기화되며, 화면 오른쪽 위에 동기화 상태가 표시됩니다.

- 🟢 서버 연동됨 / 저장됨 → 정상적으로 공유 중
- 🟡 저장 중... / 업데이트 대기 → 저장 처리 중이거나, 진행 중인 미등록 초안 보호를 위해 잠시 대기 중
- ⚪ 로컬 저장 모드 (서버 미연결) → 서버에 접속하지 못해 이 기기에만 저장되는 상태 (서버 실행/네트워크 확인 필요)
- ⚠ 표시 → 저장 실패 또는 동시편집 충돌 (아래 "주의사항" 참고)

헤더의 "나: (이름 설정)"을 클릭하면 이름을 입력할 수 있고, 이후 저장 기록에 그 이름이 표시됩니다.
(로그인 아이디는 팀 공용이라 누가 저장했는지 구분이 안 되므로, 이 이름 설정을 꼭 해두는 것을 권장합니다.)

## 6. 항상 켜두기 (서버가 꺼지면 다시 로컬 저장 모드로 전환됩니다)

서버 PC가 꺼지거나 프로그램이 종료되면 팀원들은 자동으로 각자의 로컬 저장 모드로 전환되어
계속 사용은 가능하지만, 그동안은 서로 데이터가 공유되지 않습니다. 가능하면 서버를 상시 구동해두세요.

- **Windows**: [nssm](https://nssm.cc/)이나 작업 스케줄러로 `npm start`(또는 `node server.js`)를 Windows 서비스/시작프로그램으로 등록하면 PC 재부팅 후에도 자동 실행됩니다.
- **Linux**: `systemd` 서비스로 등록하는 것을 권장합니다. 예시:

  ```ini
  # /etc/systemd/system/ehs-dashboard.service
  [Unit]
  Description=EHS Team Dashboard
  After=network.target

  [Service]
  WorkingDirectory=/path/to/server
  ExecStart=/usr/bin/node server.js
  Restart=always
  Environment=PORT=4000

  [Install]
  WantedBy=multi-user.target
  ```

  등록 후: `sudo systemctl enable --now ehs-dashboard`

- 간단하게는 서버 PC에서 터미널을 열어두고 `npm start`를 실행한 채로 두는 것만으로도 동작합니다 (터미널을 닫으면 서버도 꺼집니다).

## 7. 데이터 백업

실제 데이터는 `server/data/state.json` 파일 하나입니다. 이 파일을 주기적으로(예: 매일) 다른 곳에
복사해두면 실수로 데이터가 손상되거나 삭제되었을 때 복구할 수 있습니다. 서버는 매일 자동으로도
`server/data/backups/state_YYYY-MM-DD.json` 형태의 백업을 하나씩 남깁니다.

로그인 계정 정보는 `server/data/auth.json`에 저장됩니다(비밀번호는 원문이 아니라 해시로만
저장되어, 이 파일을 보더라도 실제 비밀번호는 알 수 없습니다).

## 8. 로그인/보안 관련 참고사항

- 이 서버는 http(암호화 안 됨)로 사내망에서 쓰는 것을 기본으로 합니다. 같은 사내망 안에서만
  접근 가능하다면 일반적으로 문제되지 않지만, 더 강한 보안이 필요하면 사내 리버스 프록시 등으로
  https를 앞에 씌우는 것을 검토해보세요. (그 경우 `server.js`의 `cookie.secure`를 `true`로 바꿔주세요.)
- 세션(로그인 유지 정보)은 서버 메모리에 저장됩니다. 서버를 재시작하면 모든 팀원의 로그인이
  풀리고 다시 로그인해야 합니다.
- 지금은 팀 전체가 아이디/비밀번호 하나를 함께 쓰는 방식입니다. 나중에 팀원별로 개별 계정을
  나누고 싶다면 말씀해주세요.

## 9. 동시편집 관련 주의사항 (중요)

이 서버는 "전체 데이터를 통째로 마지막에 저장한 내용이 우선"되는 단순한 방식입니다.
- 서로 다른 항목(예: A는 인허가, B는 프로젝트)을 동시에 수정하는 것은 문제없이 잘 반영됩니다.
- 하지만 **정확히 같은 순간에 같은 항목을 두 명이 동시에 수정**하면, 나중에 저장된 쪽이 앞의 내용을
  덮어쓸 수 있습니다. 화면 우측 상단에 🟢 저장됨 표시를 확인한 뒤 다음 작업을 진행하는 것을 권장합니다.
- 인허가/프로젝트/개선활동의 "등록" 버튼을 누르기 전 초안(임시 편집 중인 내용)은, 다른 팀원의
  업데이트가 들어와도 자동으로 덮어써지지 않고 대기했다가 등록/취소한 뒤 반영되도록 보호되어 있습니다.
- 정말 정교한 동시편집(같은 셀을 여러 명이 실시간으로 같이 편집)이 꼭 필요하다면, Firebase 같은
  실시간 동기화 서비스로 별도 전환하는 것을 검토해볼 수 있습니다 (이번 구성보다 설정이 더 필요합니다).

## 10. 오프라인/단독 사용

서버 없이 `team_calendar_dashboard.html` 파일을 그냥 더블클릭해서 열어도 기존처럼 동작합니다
(이 경우 로그인 없이 바로 열리고, 이 컴퓨터에만 데이터가 저장되며, 다른 사람과 공유되지 않습니다).
